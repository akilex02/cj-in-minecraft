# Jetpack: plan de implementación

> **Para agentes:** SUB-HABILIDAD OBLIGATORIA: usar superpowers:executing-plans (el usuario elige siempre la ejecución nativa) o superpowers:subagent-driven-development para ejecutar este plan tarea a tarea. Los pasos usan casillas (`- [ ]`).

**Objetivo:** que CJ vuele con el jetpack de GTA en Minecraft: un ítem de pechera con combustible infinito; mantener espacio eleva al jugador como un cohete, soltarlo lo deja caer despacio; con animación y modelo de GTA, llamas y humo, sonido de jetpack y sin daño de caída. Sin tocar nunca el estado real del CJ de GTA.

**Arquitectura:** el cliente de Minecraft aplica la física con reglas puras (`JetpackRules`) cada tick y manda dos bits nuevos en las banderas del `State` (`FLAG_JETPACK`, `FLAG_JETPACK_THRUST`). El puente (`BodyReactions`) reproduce con `BlendAnimation` la animación del jetpack de GTA (solo animación, nunca `CTaskSimpleJetPack`) y, según decida la investigación, dispara el audio del propio GTA con la entidad de audio del ped. El jetpack se dibuja en la espalda de CJ con el modelo de `gta3.img` (convertido como las armas). Un evento del servidor cancela el daño de caída con el jetpack puesto.

**Tecnologías:** Java 21 / Fabric 1.21.1 con Yarn (JUnit 5), C++ del puente (pruebas nativas), Python 3 (protocolo y conversor), GTA SA 1.0 US bajo Wine.

**Spec:** `docs/superpowers/specs/2026-10-07-jetpack-design.md`. Contexto: `docs/body-results.md`, `docs/climb-results.md`, `docs/climb-spike.md` (el patrón de animación mantenida con `KeepBodyAnim`).

## Global Constraints

- **Protocolo v2 sin cambiar de tamaño ni de versión.** Bits nuevos de `State.flags` (hoy usados 0 a 13): `FLAG_JETPACK` = 1<<14 (lleva el jetpack puesto y puede volar) y `FLAG_JETPACK_THRUST` = 1<<15 (empuja ahora). Los ficheros dorados no cambian (las banderas son datos).
- **El jugador real de GTA no puede sufrir nada:** nada de `CTaskSimpleJetPack` (movería al CJ de GTA por su mundo y tomaría el mando), ni cambiar la posición, la vida o las banderas del ped. Solo **animaciones** (`BlendAnimation`), el audio de su entidad de sonido y el modelo dibujado por el cliente. Al soltar la marioneta, la animación y el sonido se quitan.
- **Números iniciales** (spec §4, constantes con nombre y ajustables jugando; la Tarea 1 sustituye lo que mida): subida máxima `MAX_RISE` 0,4 bloques por tick; aceleración de subida `RISE_ACCEL` 0,16 por tick (el juego resta la gravedad de 0,08 por su cuenta, así que el aumento neto es 0,08); caída terminal `TERMINAL_FALL` −0,15; velocidad horizontal en el aire `HORIZONTAL_SPEED` 0,35 con control `AIR_CONTROL` 0,2 por tick; inclinación `MAX_TILT_DEGREES` 25.
- **Cuándo se aplica:** solo con el jetpack puesto en el slot de la pechera y permitido (no montado, no en agua ni lava, no planeando con elytra, no en escalera, no en vuelo creativo, no derribado ni muerto, no trepando). Sin GTA, el vuelo funciona como física de Minecraft (sin animación ni modelo). Con el jetpack quitado en el aire, el jugador cae con la física normal y recibe el daño normal.
- **Sin daño de caída con el jetpack puesto:** lo cancela el servidor (`ServerLivingEntityEvents.ALLOW_DAMAGE`), porque el servidor calcula su propia caída.
- Los paquetes `dev.cjmc.jetpack` (reglas puras) no usan clases de Minecraft; el ítem, el movimiento y el dibujo están en `dev.cjmc`.
- Convenciones del repo: TDD con el rojo observado, mutaciones comprobadas por el arnés (el fallo debe ser de la prueba, no de compilación; Java con `python3 tools/mutj.py <json>`, nativas escribiendo el mutante y ejecutando `bash tools/run_native_tests.sh`), commits con `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`, comentarios en inglés en el código, documentos en español.
- Comandos: Python `cd tools && python3 -B -m unittest discover -s tests` y `cd protocol && python3 -B -m unittest test_cjproto`; nativas `bash tools/run_native_tests.sh`; Java `cd cj-fabric && ./gradlew test --console=plain`.
- Abrir y cerrar los juegos con `tools/start_games.sh` (`--restart` cierra y abre ambos; GTA primero). Antes de reiniciar GTA con código nuevo del puente: `bash tools/install_bridge.sh`. La herramienta de comandos se queda esperando si se encadena el script con una tubería: redirigir su salida (`tools/start_games.sh --restart > /tmp/cj-start.log 2>&1 < /dev/null`). Cerrar procesos por PID leyendo `ps -eo pid,args` o `/proc/<pid>/cmdline`; nunca `pkill -f` ni `pgrep -f` con una cadena que contenga el propio comando. El registro del puente está en `GTA San Andreas/cj_bridge.log`.
- Hechos de GTA verificados antes: `CAnimManager::BlendAnimation(clump, grupo, id, delta)` (cdecl 0x4D4610) con el clump en `*(ped + 0x18)`; la asociación tiene peso +0x18, ritmo +0x1C, tiempo +0x20, id i16 +0x2C, banderas u16 +0x2E; bandera 0x4 = autoeliminar al desvanecerse; la lista de asociaciones del clump se recorre con `RpAnimBlendClumpGetFirstAssociation` (0x4D15E0) y `*(asoc + 4) - 4`; `KeepBodyAnim` mantiene la nuestra encima de las del propio juego; en el espacio del modelo x es adelante, y izquierda y z arriba; el modelo de un arma se convierte con `load_weapon` y se dibuja con `WeaponRig`.
- **Hechos de gta-reversed, hipótesis a verificar en vivo en la Tarea 1:** el jetpack del juego es `CTaskSimpleJetPack` (no se usa); su postura sale de `BlendAnimation(clump, ped->m_nAnimGroup, ANIM_ID_IDLE, 4.f)` con el grupo de animaciones `ANIM_GROUP_PLAYERJETPACK` = 70 («playerjetpack»: walk_player 0, run_player 1, sprint_civi 2, **jetpack_idle 3**, roadcross 4, walk_start 5); la inclinación al moverse no es una animación sino `ApplyRollAndPitch` sobre el ped; el modelo es `MODEL_JETPACK` = 370 (`jetpack.dff` y su `.txd`), dibujado en `RenderJetPack` con la matriz de un nodo del torso más un desplazamiento (0,1; 0,08; 0) y un giro de 90° sobre Y; el audio sale de la entidad de audio del ped: `CAEPedAudioEntity::TurnOnJetPack` (0x4E28A0), `UpdateJetPack(thrustFwd, thrustAngle)` (0x4E0EE0), `TurnOffJetPack` (0x4E2A70), `StopJetPackSound` (0x4E1120).

## Review Focus

1. **La partida de GTA tras soltar la marioneta:** ningún cambio de posición ni de estado en CJ, ninguna animación pegada y ningún sonido de jetpack que siga sonando si el puente se suelta (cierre de Minecraft, 1 s sin estado) o si se quita el jetpack en pleno vuelo. → Tareas 1, 6 y 9.
2. **Falsos disparadores y daño de caída:** montar, nadar, escalera, vuelo creativo, elytra, trepar, derribado y muerto no vuelan; sin jetpack hay daño de caída normal, con él no; quitarlo en el aire no deja sin daño. → Tareas 3, 4 y 5.
3. **El servidor integrado:** que mantener espacio en el aire no provoque rebotes, «flying» ilegal ni daño de caída raro con el servidor de un jugador, y que un cambio de mundo o un teletransporte no deje el vuelo en un estado raro. → Tareas 5 y 9.
4. **Sonido:** que no se acumulen sonidos superpuestos, que se corte al quitarse el jetpack, al morir, al perder GTA y al cerrar; que el empuje y el reposo suenen distinto. → Tareas 6 y 8.
5. **El jetpack con otras piezas:** que equiparlo no rompa la elytra (mismo slot), las armas en la mano, el trepado y las reacciones del cuerpo (caída libre, derribo). → Tareas 5, 6 y 9.

```java
package dev.cjmc.jetpack;

/** The rules of the jetpack: when it works and how it moves the player. Pure: the client applies them every tick. */
public final class JetpackRules {
    public static final double MAX_RISE = 0.4;          // blocks per tick (8 blocks a second)
    public static final double RISE_ACCEL = 0.16;       // per tick; the game takes its own 0.08 of gravity back, so the net gain is 0.08
    public static final double TERMINAL_FALL = -0.15;   // blocks per tick (3 blocks a second)
    public static final double HORIZONTAL_SPEED = 0.35; // blocks per tick (7 blocks a second)
    public static final double AIR_CONTROL = 0.2;       // how much of the way to the wanted speed is made each tick
    public static final double MAX_TILT_DEGREES = 25;

    private JetpackRules() {}

    public static boolean allowed(boolean wearing, boolean riding, boolean inFluid, boolean gliding, boolean climbingLadder,
                                  boolean creativeFlying, boolean knockedDown, boolean dead, boolean wallClimbing) {
        return wearing && !(riding || inFluid || gliding || climbingLadder || creativeFlying || knockedDown || dead || wallClimbing);
    }

    public static double verticalSpeed(double vy, boolean thrust) {
        return thrust ? Math.min(MAX_RISE, vy + RISE_ACCEL) : Math.max(vy, TERMINAL_FALL);
    }

    public static double horizontalSpeed(double current, double wish) {
        return current + (wish * HORIZONTAL_SPEED - current) * AIR_CONTROL;
    }

    public static double tiltDegrees(double horizontalSpeed) {
        return MAX_TILT_DEGREES * Math.min(1.0, Math.abs(horizontalSpeed) / HORIZONTAL_SPEED);
    }

    public static boolean cancelsDamage(boolean wearing, boolean fall) {
        return wearing && fall;
    }
}
```
