# Nadar y bucear: plan de implementación

> **Para agentes:** SUB-HABILIDAD OBLIGATORIA: usar superpowers:executing-plans (el usuario elige siempre la ejecución nativa) o superpowers:subagent-driven-development para ejecutar este plan tarea a tarea. Los pasos usan casillas (`- [ ]`).

**Objetivo:** que CJ flote, nade y bucee con las animaciones de GTA cuando el jugador está en el agua en Minecraft: el jugador no se hunde sino que flota con la cabeza fuera desde el primer bloque de agua, Shift lo hace descender y bucear, soltar Shift lo devuelve a la superficie, y CJ muestra las animaciones de flotar, nadar, crol, zambullida, bucear y salir. Sin tocar nunca el estado real del CJ de GTA.

**Arquitectura:** el cliente aplica la flotabilidad con reglas puras (`SwimRules`) cada tick (como el jetpack) y manda tres bits nuevos en las banderas del `State` (`FLAG_IN_WATER`, `FLAG_UNDERWATER`, `FLAG_WATER_MOVING`; el `FLAG_SWIM` existente pasa a significar el crol). El puente (`BodyReactions`) elige la animación de natación con una máquina de estados con histéresis y la reproduce con animaciones parciales creadas con `AddAnimation` (la técnica del jetpack), sin ninguna tarea de natación real de GTA. Si la investigación lo exige, el renderer inclina el cuerpo dibujado a la horizontal al nadar.

**Tecnologías:** Java 21 / Fabric 1.21.1 con Yarn (JUnit 5), C++ del puente (pruebas nativas), Python 3 (protocolo), GTA SA 1.0 US bajo Wine.

**Spec:** `docs/superpowers/specs/2026-10-08-swimming-design.md`. Contexto: `docs/jetpack-spike.md` y `docs/jetpack-results.md` (animaciones parciales con `AddAnimation`, `KeepBodyAnim`, `PadDriver` que no anda a CJ), `docs/climb-results.md`, `docs/body-results.md`.

## Global Constraints

- **Protocolo v2 sin cambiar de tamaño ni de versión.** Bits nuevos de `State.flags` (hoy usados 0 a 15): `FLAG_IN_WATER` = 1<<16 (el jugador está en el agua y la flotabilidad actúa), `FLAG_UNDERWATER` = 1<<17 (la cabeza está bajo el agua) y `FLAG_WATER_MOVING` = 1<<18 (se mueve horizontalmente en el agua; un tercer bit respecto a la spec, para que el puente no tenga que adivinar el movimiento: ruling del plan). `FLAG_SWIM` (1<<3, ya existente: la pose de nadar rápido de Minecraft) pasa a significar el crol. Los ficheros dorados no cambian (las banderas son datos).
- **El jugador real de GTA no puede sufrir nada:** nada de tareas de natación del juego (`CTaskComplexSwim`, `CTaskSimpleSwim`), ni cambiar la posición, la vida o las banderas del ped. Solo **animaciones parciales** (`AddAnimation` con la bandera parcial; nunca `BlendAnimation`, que borra las animaciones base de CJ y dejó el juego inestable en la investigación del jetpack) y el cuerpo dibujado por el cliente. Al soltar la marioneta o perder el estado, la animación puesta se quita.
- **Números iniciales** (spec §4, constantes con nombre y ajustables jugando; la Tarea 1 sustituye lo que mida): `FLOAT_DEPTH` 1,45 (los pies quedan a esa distancia bajo la superficie: los ojos, a 1,62 sobre los pies, quedan 0,17 por encima); `DIVE_SPEED` 0,08 bloques por tick (1,6 por segundo, hacia abajo con Shift); `SURFACE_SPEED` 0,12 (2,4 por segundo, hacia arriba al soltar Shift); `SINK_MAX` 0,1 (lo máximo que baja hacia la altura de flotación desde arriba); `GAIN` 0,25 (la suavidad: la fracción del error de altura que se corrige cada tick); `MOVING_SPEED` 0,03 bloques por tick (por debajo, quieto); `MIN_STATE_MS` 250 (el tiempo mínimo entre dos cambios de animación en la superficie); `kDiveMs` y `kExitMs` las duraciones medidas en la Tarea 1 (≈ 700 ms cada una hasta entonces).
- **Cuándo se aplica:** solo en agua (no lava), no montado, no con el jetpack volando, no planeando con elytra, no en escalera, no en vuelo creativo ni espectador, no derribado, muerto ni trepando. Sin GTA, el jugador flota y bucea igualmente (es física de Minecraft) sin animaciones. Espacio no cambia: lo lleva Minecraft (nadar hacia arriba y salir en una orilla); con espacio pulsado la flotabilidad no toca la velocidad vertical.
- **Shift es la tecla física de agacharse** (`client.options.sneakKey`), no el agachado forzado que el mod aplica al pegar o apuntar (`SneakRules`).
- Los paquetes `dev.cjmc.swim` (reglas puras) no usan clases de Minecraft; el movimiento, la lectura del agua y el dibujo están en `dev.cjmc` (cliente).

## Review Focus

1. **La partida de GTA tras soltar la marioneta:** ningún cambio de posición ni de estado en CJ, ninguna animación pegada si el puente se suelta (cierre de Minecraft, 1 s sin estado) nadando o buceando; las animaciones base de CJ siguen vivas. → Tareas 1, 5 y 8.
2. **Flotabilidad y servidor:** que flotar no provoque rebotes ni expulsión en el servidor integrado, que la distancia de caída del servidor no se acumule al flotar o bucear (como pasó con el jetpack), y que salir del agua o caer a ella no haga daño de caída raro. → Tareas 3, 4 y 8.
3. **Falsos disparadores y condiciones:** lava, cascadas, columnas de burbujas, waterlogged, charcos de un bloque, agua con el suelo cerca; montar, escalera, vuelo creativo, elytra, jetpack, trepar, derribado y muerto no flotan. → Tareas 3 y 4.
4. **Animaciones que parpadean:** cambios rápidos entre flotar y nadar al empezar o dejar de moverse, al entrar y salir del agua y al pasar el agua poco honda; que la zambullida y la salida no se repitan. → Tarea 5 (histéresis con tiempos).
5. **Convivencia con otras piezas:** el jetpack (no vuela en el agua y viceversa), el trepado (salir del agua trepando una orilla), la caída libre, las armas en la mano y las reacciones del cuerpo. → Tareas 4, 5 y 8.

```java
package dev.cjmc.swim;

/** The rules of swimming: when the buoyancy works and where it takes the player vertically. Pure: the client applies them every tick. */
public final class SwimRules {
    public static final double FLOAT_DEPTH = 1.45;    // blocks of the feet below the surface when floating (the eyes, 1.62 above them, stay 0.17 above the water)
    public static final double DIVE_SPEED = 0.08;     // blocks per tick going down with Shift (1.6 blocks a second)
    public static final double SURFACE_SPEED = 0.12;  // blocks per tick coming up at most (2.4 blocks a second)
    public static final double SINK_MAX = 0.1;        // blocks per tick going down at most toward the float height from above
    public static final double GAIN = 0.25;           // the share of the height error corrected each tick
    public static final double MOVING_SPEED = 0.03;   // blocks per tick of horizontal speed above which he counts as moving

    private SwimRules() {}

    public static boolean allowed(boolean inWater, boolean riding, boolean jetpackFlying, boolean gliding, boolean climbingLadder,
                                  boolean creativeFlying, boolean knockedDown, boolean dead, boolean wallClimbing) {
        return inWater && !(riding || jetpackFlying || gliding || climbingLadder || creativeFlying || knockedDown || dead || wallClimbing);
    }

    public static double floatHeight(double surfaceY) {
        return surfaceY - FLOAT_DEPTH;
    }

    /**
     * The vertical speed after this tick. Space is Minecraft's (swim up: left as it is); Shift dives at a fixed speed; otherwise the
     * buoyancy takes him toward the float height, coming up no faster than SURFACE_SPEED and going down no faster than SINK_MAX.
     */
    public static double verticalSpeed(double vy, double feetY, double surfaceY, boolean diving, boolean ascending) {
        if (ascending) {
            return vy;
        }
        if (diving) {
            return -DIVE_SPEED;
        }
        double error = floatHeight(surfaceY) - feetY;
        return Math.max(-SINK_MAX, Math.min(SURFACE_SPEED, error * GAIN));
    }

    public static boolean moving(double horizontalSpeedPerTick) {
        return Math.abs(horizontalSpeedPerTick) > MOVING_SPEED;
    }
}
```
