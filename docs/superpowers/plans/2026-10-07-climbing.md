# Trepar muros de 2 y 3 bloques: plan de implementación

> **Para agentes:** SUB-HABILIDAD OBLIGATORIA: usar superpowers:executing-plans (el usuario elige siempre la ejecución nativa) o superpowers:subagent-driven-development para ejecutar este plan tarea a tarea. Los pasos usan casillas (`- [ ]`).

**Objetivo:** que CJ trepe automáticamente (saltando contra el muro) muros de 2 y 3 bloques con las animaciones de GTA, acabando de pie sobre el borde, con el jugador inmovilizado mientras dura y sin cambiar nunca el estado real del CJ de GTA.

**Arquitectura:** el cliente de Minecraft detecta el muro con reglas puras (`ClimbRules`) alimentadas por una lectura fina del mundo, y mueve al jugador por un arco calculado por una sesión pura (`ClimbSession`/`ClimbPath`) comprobando cada tick que la caja de colisión cabe. Una bandera nueva del `State` (`FLAG_WALL_CLIMB`, 1<<13) avisa al puente, cuya máquina de estados pura (`BodyReactions`) reproduce la animación de GTA con `BlendAnimation` (solo animación, nunca tareas del juego). `BodyClient.frozen()` incluye el trepado para que los mixins de entrada y de ataque ya existentes lo respeten.

**Tecnologías:** Java 21 / Fabric 1.21.1 con Yarn (JUnit 5), C++ del puente (pruebas nativas), Python 3 (protocolo), GTA SA 1.0 US bajo Wine.

**Spec:** `docs/superpowers/specs/2026-10-07-climbing-design.md`. Contexto: `docs/body-results.md`, `docs/body-spike.md`, `docs/m4-effects-results.md`.

## Global Constraints

- **Protocolo v2 sin cambiar de tamaño ni de versión.** Bit nuevo de `State.flags`: `FLAG_WALL_CLIMB` = 1<<13 (hoy usados 0 a 12: ON_GROUND, SPRINT, SNEAK, SWIM, CLIMBING, FALLING, KNOCKED, DEAD, contador de daños en 8 a 11, BLASTED en 12). `FLAG_CLIMBING` (escaleras) no cambia. Los ficheros dorados no cambian (las banderas son datos).
- **El jugador real de GTA no puede sufrir nada:** nada de `CTaskComplexClimb`, `CTaskSimpleClimb` ni otra tarea de trepar del juego (moverían a CJ en el mundo de GTA). Solo **animaciones** (`BlendAnimation`). La vida, la posición y las banderas del ped de GTA no se tocan. Al soltar la marioneta o perder el estado, la animación puesta se quita (ya lo hace `Release`).
- **Números iniciales** (spec §4, constantes con nombre y ajustables jugando; la Tarea 1 sustituye las duraciones por las medidas): altura trepable 2 o 3 bloques; hueco libre mínimo encima del borde 2 bloques; alcance del muro 0,6 bloques; avance final sobre el borde 0,6 bloques; subida `RISE_MS` 700 y avance `FORWARD_MS` 400; tope de vigilancia: la sesión termina sola a `TOTAL_MS` (= `RISE_MS + FORWARD_MS`) y con un reloj que salta o va hacia atrás.
- **Cuándo se aplica:** solo con CJ dibujado (`CjClient.bridgeLive()` y `CjRenderer.INSTANCE.hasFreshPose()`); sin GTA no hay trepado automático y el salto es el de Minecraft. Nunca montando, nadando (agua o lava), en una escalera, volando, planeando con elytra, derribado ni muerto; con sneak pulsado tampoco.
- **Inmovilización con vigilante:** el jugador queda inmovilizado como mucho lo que dura la sesión (por el temporizador, no por una bandera que pudiera quedarse puesta); si GTA deja de responder (`drawn` falso) o el jugador muere, la sesión se cancela y se libera en el acto.
- **Derribo durante el trepado:** se aplaza: `BodyClient` no consume la cola de derribos del servidor mientras trepa (queda en `CjBody` y se aplica al terminar). La muerte gana: cancela el trepado.
- Los paquetes `dev.cjmc.climb` (reglas y sesión puras) no usan clases de Minecraft; la lectura del mundo y el movimiento están en `dev.cjmc.ClimbController` (cliente).
- Convenciones del repo: TDD con el rojo observado, mutaciones comprobadas por el arnés (el fallo debe ser de la prueba, no de compilación; Java con `python3 tools/mutj.py <json>`, nativas escribiendo el mutante y ejecutando `bash tools/run_native_tests.sh`), commits con `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`, comentarios en inglés en el código, documentos en español.
- Comandos: Python `cd tools && python3 -B -m unittest discover -s tests` y `cd protocol && python3 -B -m unittest test_cjproto`; nativas `bash tools/run_native_tests.sh`; Java `cd cj-fabric && ./gradlew test --console=plain`.
- Abrir y cerrar los juegos con `tools/start_games.sh` (`--restart` cierra y abre ambos; GTA primero). Antes de reiniciar GTA con código nuevo del puente: `bash tools/install_bridge.sh`. La herramienta de comandos se queda esperando si se encadena el script con una tubería: redirigir su salida a un fichero (`tools/start_games.sh --restart > /tmp/cj-start.log 2>&1 < /dev/null`). Cerrar procesos por PID leyendo `ps -eo pid,args` o `/proc/<pid>/cmdline`; nunca `pkill -f` ni `pgrep -f` con una cadena que contenga el propio comando.
- Hechos de GTA verificados en la reacción del cuerpo: `CAnimManager::BlendAnimation(clump, grupo 0, id, delta)` (cdecl 0x4D4610) con el clump en `*(ped + 0x18)`; la asociación (con tabla virtual) tiene peso +0x18, ritmo +0x1C, tiempo +0x20, velocidad +0x24, id i16 +0x2C, banderas u16 +0x2E; bandera 0x4 = autoeliminar al desvanecerse. ## Review Focus

1. **La partida de GTA tras soltar la marioneta:** ningún cambio de posición ni de estado en CJ y ninguna animación pegada si el puente se suelta (cierre de Minecraft, 1 s sin estado) a mitad de trepar. → Tareas 1, 5 y 7.
2. **Falsos disparadores:** saltos normales (1 bloque, escalones, losas, escaleras de bloque) no activan el trepado; agua, montar, escalera, volar, elytra, derribado y sneak no lo activan. → Tareas 3 y 6.
3. **Sin atravesar bloques:** un bloque puesto o roto a mitad, un techo bajo o un muro de 4 cancelan o rechazan el trepado sin dejar al jugador dentro de un bloque. → Tareas 3, 4 y 6.
4. **Inmovilización que no se suelta:** con la sesión vencida, GTA sin responder, la muerte o un cambio de mundo, el control vuelve en menos de `TOTAL_MS`. → Tareas 4 y 6.
5. **Convivencia con el salto retrasado y los derribos:** un solo trepado por salto (sin salto doble ni trepado repetido manteniendo espacio), y un derribo del servidor durante el trepado se aplica después, no se pierde ni encadena. → Tareas 4 y 6.

```java
package dev.cjmc.climb;

/** Whether a jump against a wall becomes a climb, and how high: pure rules over what the world around the player looks like. */
public final class ClimbRules {
    public static final int MIN_HEIGHT = 2;   // blocks; one block is the normal jump of Minecraft
    public static final int MAX_HEIGHT = 3;
    public static final int CLEAR_ABOVE = 2;  // free blocks the body needs on top of the ledge

    private ClimbRules() {}

    /** The height of the climb (MIN_HEIGHT or MAX_HEIGHT) or 0 when the player just jumps. */
    public static int heightOf(int wallBlocks, int clearAbove, boolean standable, boolean pushing, boolean onGround,
                               boolean sneaking, boolean eligible) {
        if (!eligible || !pushing || !onGround || sneaking || !standable || clearAbove < CLEAR_ABOVE) {
            return 0;
        }
        return wallBlocks >= MIN_HEIGHT && wallBlocks <= MAX_HEIGHT ? wallBlocks : 0;
    }

    public static boolean eligible(boolean riding, boolean inFluid, boolean climbing, boolean flying, boolean gliding,
                                   boolean frozen, boolean dead) {
        return !(riding || inFluid || climbing || flying || gliding || frozen || dead);
    }
}
```

```java
package dev.cjmc.climb;

/** Where the player is during a climb: first he rises along the wall, then he moves forward onto the ledge. */
public final class ClimbPath {
    public static final long RISE_MS = 700;        // initial values; replaced by what docs/climb-spike.md measured
    public static final long FORWARD_MS = 400;
    public static final double FORWARD_BLOCKS = 0.6;
    public static final long TOTAL_MS = RISE_MS + FORWARD_MS;

    private ClimbPath() {}

    public static double rise(int height, long elapsedMs) {
        return height * fraction(elapsedMs, RISE_MS);
    }

    public static double forward(long elapsedMs) {
        return FORWARD_BLOCKS * fraction(elapsedMs - RISE_MS, FORWARD_MS);
    }

    public static boolean done(long elapsedMs) {
        return elapsedMs >= TOTAL_MS;
    }

    private static double fraction(long elapsedMs, long durationMs) {
        return Math.max(0.0, Math.min(1.0, (double) elapsedMs / durationMs));
    }
}
```

```java
package dev.cjmc.climb;

/** One climb under way: it ends by itself when the path is over, and a watchdog ends it if the clock misbehaves. */
public final class ClimbSession {
    private boolean started;
    private long startMs;
    private int height;

    public void start(int height, long nowMs) {
        if (height < ClimbRules.MIN_HEIGHT || height > ClimbRules.MAX_HEIGHT) {
            throw new IllegalArgumentException("height " + height);
        }
        this.height = height;
        startMs = nowMs;
        started = true;
    }

    public boolean active(long nowMs) {
        return started && nowMs >= startMs && nowMs - startMs < ClimbPath.TOTAL_MS;
    }

    public double rise(long nowMs) {
        return ClimbPath.rise(height, nowMs - startMs);
    }

    public double forward(long nowMs) {
        return ClimbPath.forward(nowMs - startMs);
    }

    public int height() {
        return height;
    }

    public void cancel() {
        started = false;
    }
}
```

  El vigilante es el propio final del arco: `active` es falso para cualquier tiempo transcurrido fuera de `[0, TOTAL_MS)`, también con un reloj que salta o va hacia atrás.
